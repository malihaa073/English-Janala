Frequently Asked Questions

In JavaScript, var is function-scoped, can be re-declared, and is hoisted to the top of its scope with an initial value of undefined. It is less recommended in the code. let is block-scoped, cannot be re-declared, and is hoisted without initialization, making it inaccessible until it is initialized (temporal dead zone). Similarly, const is block-scoped, cannot be re-declared or reassigned, and is also hoisted without initialization, remaining in the temporal dead zone until its declaration. let is preferred for variables that need to be updated, while const is ideal for constants whose values shouldn’t change.
map() transforms each element in an array and returns a new array of the same length with the transformed elements. It is used when you need to modify or map each element to a new value. forEach() iterates over each element in an array to perform an action but does not return anything. It is useful when you need to execute a function on each element without creating a new array. filter() is used to create a new array containing only the elements that match a specified condition, filtering out the rest.
Arrow functions in JavaScript offer a concise syntax for writing functions. When an arrow function contains a single expression, it can omit the curly braces and the explicit return statement—this is known as an implicit return. Unlike regular functions, arrow functions do not have their own this binding; they inherit this from their surrounding lexical scope, which simplifies handling context in callbacks and event handlers. They also lack their own arguments object and cannot be used as constructors, marking key differences from regular functions.
In JavaScript, Promises represent the result of an asynchronous operation. They have three states: pending (ongoing), fulfilled (successful, resolved with a value), or rejected (failed, with an error). You create a Promise using the Promise constructor, handle results with .then() for success, .catch() for errors, and .finally() for cleanup. Promises can be chained for sequential operations, making asynchronous code cleaner and easier to manage compared to callbacks.
Closures in JavaScript allow a function to retain access to its outer (lexical) scope even after the outer function has finished executing. This means that an inner function "remembers" the variables and parameters of the function in which it was created. For example, when you define a function inside another function, the inner function can use variables from the outer function even after that outer function has returned. This feature is especially useful for creating private variables or functions, as it lets you encapsulate state that persists over time without exposing it directly. Essentially, closures enable powerful patterns in JavaScript such as function factories, module patterns, and event handlers that maintain state between invocations.
